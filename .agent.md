# Telegram LLM Bot Framework - Developer Guide

## Project Overview

This is a flexible Telegram bot framework that supports multiple AI-powered bot personalities with LLM-driven responses, periodic engagement, and image generation capabilities. The framework is built in Python using the `python-telegram-bot` library and integrates with OpenRouter's LLM API for intelligent conversations.

### Key Technologies
- **Language**: Python 3.x
- **Framework**: python-telegram-bot (v20.7+)
- **LLM Provider**: OpenRouter API
- **Image Generation**: Modelslab API
- **Deployment**: Heroku-ready (Procfile included)
- **Environment Management**: python-dotenv

## Architecture & Structure

### Core Components
- `src/bot/telegram_bot.py` - Main bot class with LLM integration and periodic responses
- `src/config/config.py` - Configuration management and data classes
- `src/handlers/handlers.py` - Telegram event handlers (commands, messages, new members)
- `src/services/llm_client.py` - LLM API client with retry logic and error handling
- `src/services/chat_data.py` - Chat history management and data structures
- `src/utils/helpers.py` - Utility functions for user handling

### Configuration Files
- `config/bots_config.json` - Bot personality configurations
- `src/prompts/` - System prompt files for each bot personality
- `.env` - Environment variables (not committed)
- `requirements.txt` - Python dependencies

## Development Best Practices

### Code Organization
- Follow the existing modular structure with separate services, handlers, and utilities
- Keep bot-specific logic in configuration files rather than hardcoding
- Use dataclasses for structured data (BotConfig, ChatData)
- Implement proper error handling with retry mechanisms

### Configuration Management
- All bot configurations should be defined in `config/bots_config.json`
- Environment variables follow the pattern: `{ENV_PREFIX}BOT_TOKEN`, `{ENV_PREFIX}OPENROUTER_API_KEY`
- System prompts are stored as separate text files in `src/prompts/`
- Use the ConfigLoader class for loading and validating configurations

### Message Handling
- All responses must be plain text (no markdown formatting)
- Never prefix responses with bot names (e.g., "Kovu:", "Kenji:")
- Keep responses concise (2-3 sentences typically)
- Use first-person perspective only ("I", "me", "my")
- Avoid narration or action descriptions
- Immediate responses for mentions, replies, questions, and commands
- Smart @mention system that avoids spam
- Conversation flow management to prevent over-chatting

### LLM Integration
- Use the LLMClient class for all OpenRouter API interactions
- Implement proper timeout handling (30s for regular, 60s for periodic)
- Include retry logic with exponential backoff
- Perform network health checks before API calls
- Log all LLM interactions for debugging

### Chat History Management
- Maintain rolling message history (default: 20 messages)
- Track new activity flags for periodic response triggers
- Store user metadata (username, user_id) with messages
- Use ChatHistoryManager for consistent data handling

## Environment Setup

### Required Environment Variables
```bash
# For each bot (replace PREFIX with bot's env_prefix from config)
{PREFIX}_BOT_TOKEN=your_telegram_bot_token
{PREFIX}_OPENROUTER_API_KEY=your_openrouter_api_key

# Optional global fallback
OPENROUTER_API_KEY=your_global_openrouter_api_key

# Optional logging level
{PREFIX}_LOG_LEVEL=INFO
```

### Running Bots
```bash
# Run specific bot
python src/bot/telegram_bot.py --bot <botname>

# Examples
python src/bot/telegram_bot.py --bot kovubot
python src/bot/telegram_bot.py --bot kenjibot
python src/bot/telegram_bot.py --bot narlybot
```

## Key Features Implementation

### Response System
- **Immediate Responses**: Bot responds instantly to:
  - Direct @mentions (`@botusername`)
  - Replies to bot messages
  - Questions containing bot name
  - Greetings with bot mention
  - All messages in private chats
- **Periodic Responses**: Automatic responses every 30 seconds for general conversation
  - Smart @mention system (only 30% chance for general chat)
  - Avoids consecutive bot messages
  - Skips when bot has been too active recently
- **Context-Aware**: All responses use full conversation history

### Command Handlers
- `/start` - Triggers welcome message and starts periodic responses
- `/draw [prompt]` - Generate images using Modelslab API
- New member welcome messages

### Error Handling
- Comprehensive logging with different levels per component
- Graceful degradation when APIs are unavailable
- Network health checks before expensive operations
- User-friendly error messages that maintain bot personality

## Adding New Bots

### 1. Configuration
Add new bot entry to `config/bots_config.json`:
```json
{
  "newbot": {
    "system_prompt_file": "src/prompts/newbot_system_prompt.txt",
    "env_prefix": "NEWBOT_",
    "bot_name_display": "NewBot",
    "bot_username_internal": "newaibot",
    "openrouter_model": "qwen/qwen3-32b:free",
    "welcome_message_template": "Welcome, {member_full_name}!"
  }
}
```

### 2. System Prompt
Create `src/prompts/newbot_system_prompt.txt` with personality definition

### 3. Environment Variables
Set up required environment variables:
```bash
NEWBOT_BOT_TOKEN=your_token
NEWBOT_OPENROUTER_API_KEY=your_key
```

### 4. Deploy
Run with: `python src/bot/telegram_bot.py --bot newbot`

## Security Considerations

### API Keys
- Never commit API keys to version control
- Use environment variables for all sensitive data
- Implement proper SSL context for HTTPS requests
- Use separate API keys per bot when possible

### Input Validation
- Validate all user inputs before processing
- Sanitize message content before LLM processing
- Implement rate limiting through OpenRouter
- Log security-relevant events

## Troubleshooting

### Common Issues
- **Bot not responding**: Check BOT_TOKEN and bot permissions
- **LLM errors**: Verify OPENROUTER_API_KEY and model availability
- **Image generation fails**: Check Modelslab API key and quota
- **Periodic jobs not working**: Ensure proper chat initialization

### Debugging
- Enable DEBUG logging: `{PREFIX}_LOG_LEVEL=DEBUG`
- Check network connectivity with health checks
- Monitor API response logs
- Verify configuration file syntax

## File Naming Conventions

### Ignored Files
The `.gitignore` includes several bot-specific files that should not be committed:
- Individual bot scripts (e.g., `kenji_bot.py`, `kovu_bot.py`)
- Log files (e.g., `kovubot.log`)
- Legacy implementations
- Only `general_bot.py` is allowed if present

### Prompt Files
- Use descriptive names: `{botname}_system_prompt.txt`
- Store in `src/prompts/` directory
- Use UTF-8 encoding
- Keep prompts focused and personality-specific
